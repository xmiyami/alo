## 2. Картина всей работы
Есть сценарий, интерпретатор и управляемые программы. Сценарий — текст с инструкциями. Интерпретатор VBScript или JScript понимает эти инструкции. Хост WSH предоставляет окружение для их выполнения. Через COM-объект оболочки сценарий запускает приложения и обращается к их окнам. Операционная система управляет процессами, окнами, файловой системой и буфером обмена.
В третьем задании маршрут такой: строка файла → проверка синтаксиса → перевод входных чисел во внутренние значения → дерево операций → запросы Калькулятору → перевод ответа в выбранное основание → выходной файл.
Не смешивайте четыре вещи: язык JScript, хост cscript.exe, библиотеку Scripting.FileSystemObject и приложение Калькулятор. Они выполняют разные роли.

## 3. Файлы, пути и командная строка Windows
Полный путь содержит диск и каталог: C:\STUDENT\ИИ-551\Lab4\script3.js. Относительный путь text1.txt зависит от текущего каталога. В коде путь через WScript.ScriptFullName привязывает поиск к месту самого сценария и не зависит от того, откуда его запустили.
```bat
mkdir "C:\STUDENT\ИИ-551\Lab4"
cd /d "C:\STUDENT\ИИ-551\Lab4"
dir
notepad text1.txt
cscript.exe //nologo //E:JScript script3.js
```
| Команда | Как прочитать и что произойдёт |
| mkdir "каталог" | Создать папку для файлов лабораторной. |
| cd /d "каталог" | Сменить текущий диск и папку. Без /d смена диска может не произойти. |
| dir | Посмотреть список файлов; это первый шаг при ошибке «Файл не найден». |
| notepad имя | Открыть указанный файл в Блокноте. |
| cscript.exe //nologo script1.vbs | Выполнить VBScript в консоли, без баннера. |
| cscript.exe //nologo //E:JScript script3.js | Выполнить через JScript явно; не использовать браузерную ассоциацию .js. |
| wscript.exe script1.vbs | Выполнить через оконный хост. |
| echo %errorlevel% | В cmd сразу после запуска показать код завершения; промежуточные команды могут его изменить. |
| where cscript | Найти cscript.exe по системному PATH. Это поиск программы, а не проверка корректности сценария. |
Кавычки защищают путь с пробелами. Расширение важно: script1.vbs.txt — текстовый файл, не сценарий .vbs. Включите «Проводник → Вид → Показать → Расширения имён файлов». Не запускайте файлы прямо из ZIP: сначала распакуйте весь комплект.

## 4. WScript, Shell и COM
| Объект | Откуда берётся | Для чего нужен |
| WScript | Предоставляется WSH автоматически. | Sleep, Echo, Quit, ScriptFullName, Arguments. |
| WScript.Shell | CreateObject или ActiveXObject. | Run, Exec, AppActivate, SendKeys, Popup. |
| Scripting.FileSystemObject | CreateObject или ActiveXObject. | Файлы, папки и текстовые потоки. |
COM — механизм Windows, позволяющий программам обращаться к объектам с определёнными методами и свойствами. Для защиты достаточно понимать: сценарий получает объект, а затем вызывает его методы. Не всякое приложение предоставляет COM-автоматизацию; запуск calc.exe через Run не означает, что у Калькулятора есть доступный объект Calculator.Application.
```vb
Option Explicit
Dim sh
Set sh = CreateObject("WScript.Shell")
WScript.Echo "Объект оболочки создан"
```
```js
var sh = new ActiveXObject("WScript.Shell");
WScript.Echo("Объект оболочки создан");
```
В VBScript Set присваивает ссылку на объект. В JScript используется обычное присваивание. Метод — действие, например Run(...). Свойство — значение, например WScript.ScriptFullName. Не путайте строку "WScript.Shell" с именем переменной sh: переменную можно назвать иначе, COM-имя объекта должно оставаться правильным.

## 5. Минимум VBScript для чтения первых двух сценариев
| Синтаксис | Пояснение |

| Dim sh, i | Объявление переменных. Тип определяется во время работы. |

| If условие Then ... End If | Условное выполнение. |
| For i = 1 To 30 ... Next | Цикл с 30 значениями счётчика. |

## 6. Запуск и ожидание: Run и Exec
```vb
sh.Run "calc.exe", 1, False
WScript.Sleep 2000
```
Run(command, windowStyle, wait) запускает команду. Первый аргумент — командная строка; второй — способ отображения; третий — ждать ли завершения. False удобно для Калькулятора: сценарий продолжает работать, пока приложение открыто. Если поставить True для обычного запуска Калькулятора, сценарий может ждать его закрытия вместо передачи клавиш.
Run с ожиданием возвращает код завершения. Значение Run без ожидания не является PID. Exec возвращает объект процесса с ProcessID, Status, ExitCode и потоками StdIn, StdOut, StdErr. Exec полезен для консольных утилит; он не заменяет механизм управления GUI.
```js
var sh = new ActiveXObject("WScript.Shell");
var command = sh.ExpandEnvironmentStrings("%COMSPEC%") + " /c echo LAB4";
var process = sh.Exec(command);
WScript.Echo(process.StdOut.ReadAll());
while (process.Status === 0) WScript.Sleep(100);
WScript.Echo("ExitCode: " + process.ExitCode);
```
Это маленький учебный вывод, не шаблон для больших потоков: при большом объёме вывода нельзя бесконтрольно ждать завершения, не читая stdout/stderr, иначе возможна блокировка заполненных буферов. %COMSPEC% — путь к командному интерпретатору, /c — выполнить команду и завершиться.
WScript.Sleep измеряется в миллисекундах: 500 = 0.5 с, 2000 = 2 с. Пауза нужна, потому что интерфейс реагирует не мгновенно. Ожидание условия с ограничением времени надёжнее одной фиксированной паузы.

## 7. Процесс, окно и AppActivate
PID — идентификатор процесса, HWND — дескриптор окна. В учебном разговоре нельзя называть их одним и тем же числом. Одно приложение может иметь несколько процессов и окон.
AppActivate("Калькулятор") пытается найти окно по заголовку и активировать его. При успехе возвращает True. Метод не выполняет арифметику, не запускает отсутствующее приложение и не гарантирует, что пользователь не сменит фокус через мгновение.
Алгоритм ActivateCalc: до 30 попыток → русское/английское имя → при успехе пауза и выход → иначе пауза и повтор → после лимита сообщение и Quit(1). При нескольких окнах с одинаковыми заголовками выбор может оказаться неоднозначным.
В исходной версии VBScript выражение A Or B вычисляет обе части: короткого замыкания нет. Поэтому даже успешная первая активация не исключает второго вызова. Вариант If ... ElseIf ... позволяет выполнять проверки последовательно. В JScript логические || и && обычно используют короткое замыкание.

## 8. SendKeys: шпаргалка
SendKeys отправляет имитацию клавиатурного ввода активному окну. Он не принимает произвольный текст как надёжную независимую от раскладки запись. Для русских подписей предпочтительнее Unicode-файл или другой прямой механизм передачи текста.
| Строка | Интерпретация |
| 9*6= | Ввод выражения в Калькулятор. |
| ^c | Ctrl+C. Результат копирования определяется активным приложением. |
| ^v | Ctrl+V. |
| %1 / %3 | Alt+1 / Alt+3. В используемом Калькуляторе — обычный режим / программист. |
| +a | Shift+A. |
| {+} | Буквальный знак +, а не модификатор Shift. |
| {ENTER} | Клавиша Enter. |
| {ESC} | Escape; в Калькуляторе очищает текущее состояние в используемом режиме. |
| {TAB} | Tab, переход фокуса. |
| {F5} / {F6} | Функциональные F5 / F6; HEX / DEC в режиме программиста. |
| {F9} | Смена знака в используемом Калькуляторе. |
| F7 | Символы F и 7, число F7₁₆ при HEX-вводе. |
| {F7} | Функциональная клавиша; OCT в режиме программиста. |
| {LEFT}, {RIGHT}, {HOME}, {END} | Навигационные клавиши. |
Спецсимволы +, ^, %, ~, (, ), {, } требуют особой записи, если должны вводиться буквально. Например, круглые скобки группируют клавиши под модификатором; для буквальных скобок применяются {(} и {)}. Для + корректный пример в лабораторной — F7{+}7F=.
Частая ошибка: послать ^c, когда активен Блокнот, а не Калькулятор. Ещё одна — переключить окно мышью во время сценария. Правильное число в Калькуляторе при пустом выходе обычно направляет поиск ошибки к фокусу и обмену, а не к умножению.

## 9. Диалоги: Popup и MsgBox
Popup принадлежит WScript.Shell и доступен из обоих языков. MsgBox — встроенная функция VBScript. В Popup указываются текст, тайм-аут, заголовок и тип окна.
```js
var sh = new ActiveXObject("WScript.Shell");
var answer = sh.Popup("Продолжить?", 0, "Учебный пример", 3 + 32);
WScript.Echo("Код выбранной кнопки: " + answer);
```
| Число | Значение в Popup |
| 0 в параметре тайм-аута | Ждать ответа без ограничения. |
| 3 в параметре типа | Кнопки Да / Нет / Отмена. |
| 32 в параметре типа | Значок вопроса; тип 3 + 32 = 35. |
| 1 / 2 / 6 / 7 в результате | ОК / Отмена / Да / Нет. |
| -1 в результате | Истёк заданный ненулевой тайм-аут. |
Для выбора четырёх оснований одного стандартного диалога с тремя кнопками недостаточно. Поэтому сценарий задаёт последовательность вопросов. Важно проследить все ветви: в старом чужом образце вариант DEC оказался недоступен, хотя текст диалога его обещал.

## 10. FileSystemObject и кодировки
```js
var fso = new ActiveXObject("Scripting.FileSystemObject");
var dir = fso.GetParentFolderName(WScript.ScriptFullName);
var file = fso.OpenTextFile(dir + "\\text1.txt", 1, false, 0);
while (!file.AtEndOfStream) WScript.Echo(file.ReadLine());
file.Close();
```
В строковом литерале JScript обратная косая черта экранируется: "\\" означает одну косую черту в фактическом пути. В VBScript обратная косая черта не требует такого удвоения.
| Метод / значение | Назначение |
| FileExists(path) | Есть ли файл. Правильное имя во множественном числе: Exists. |
| FolderExists(path) | Есть ли каталог. |
| BuildPath(a,b) | Составить путь из каталога и имени. |
| GetParentFolderName(path) | Получить родительский каталог. |
| OpenTextFile(path, 1, false, 0) | Чтение существующего файла в ANSI-режиме. |
| Режимы 1 / 2 / 8 | Чтение / запись / добавление в конец. |
| CreateTextFile(path, true, true) | Перезаписать или создать Unicode UTF-16LE-файл. |
| ReadLine / ReadAll | Прочитать строку / весь оставшийся текст. |
| AtEndOfStream | Достигнут ли конец потока. |
| Write / WriteLine | Записать текст без / с переводом строки. |
| Close | Закрыть поток, освободить ресурс. |
| DeleteFile(path) | Удалить файл. В лабораторной — собственные временные запросы/ответы. |
| GetSpecialFolder(2) | Системный временный каталог. |
| GetTempName() | Получить имя для временного файла; само содержимое создаётся отдельно. |
Для OpenTextFile формат 0 — ASCII/ANSI в терминологии FSO, -1 — Unicode UTF-16, -2 — системный формат по умолчанию. Это не универсальный UTF-8-декодер. true в третьем аргументе CreateTextFile означает Unicode, а true во втором — перезапись; одинаковое слово занимает разные позиции и имеет разный смысл.
ASCII — общий набор латинских символов и цифр. UTF-8 и UTF-16 — разные кодировки Unicode. BOM — сигнатура в начале файла. Текущий входной reader не удаляет UTF-8 BOM; первый символ тогда может вызвать ошибку. Для лабораторной проще сохранять ASCII-содержимое без BOM. Перезаписываемые результаты следует копировать под другим именем перед следующим запуском.

## 12. Регулярные выражения из программы
| Выражение | Что проверяет или меняет |
| /\s/ | Один пробельный символ. |
| /^\s*$/ | Вся строка состоит из нуля или более пробельных символов. ^ и $ — границы строки. |
| /[0-9]/ | Одна десятичная цифра. |
| /[0-9a-fA-F.]/ | Символ-кандидат для числа: цифра, A–F или точка. Дальше нужна проверка выбранного основания. |
| /0+$/ | Один или более нулей в конце строки; удаляет завершающие нули дробной части. |
| /^(-?)(0x\|@)/ | В начале записи найти необязательный минус и префикс; $1 в замене сохраняет знак. |
| /^(-?)0(?=[0-7])/ | Удалить ведущий восьмеричный префикс перед следующей цифрой, сохраняя знак. (?=...) — проверка вперёд без поглощения символов. |
Не путайте ^ внутри строки SendKeys (^c — Ctrl+C) и ^ в регулярном выражении (начало строки). Значение символа зависит от языка и контекста.

## 13. Системы счисления с нуля
Основание b определяет набор цифр и вес позиции. В двоичной системе цифры 0 и 1; в восьмеричной 0…7; в десятичной 0…9; в шестнадцатеричной 0…9 и A…F, где A=10, B=11, C=12, D=13, E=14, F=15.
| Запись входа | Основание | Значение DEC |
| 0xF7 | 16 | 15 × 16 + 7 = 247. |
| 010 | 8 | 1 × 8 + 0 = 8. |
| @101 | 2 | 1 × 4 + 0 × 2 + 1 = 5. |
| 10 | 10 | Десять. |
| 0.5 | 10 | Одна вторая; после начального нуля стоит точка. |
| 010.4 | 8 | 8 + 4/8 = 8.5. |
Входные префиксы — соглашение этой программы. Символ @ не является универсальным стандартом двоичных чисел во всех языках. Из записи 010 в текстовом файле основание определяет наш парсер, а не автоматический разбор числового литерала движком JScript.
Для перевода целого из b в DEC умножайте накопленное значение на b и добавляйте цифру. Для @101: 0×2+1=1, 1×2+0=2, 2×2+1=5. Для дроби вес первой цифры — 1/b, второй — 1/b² и так далее.
Для перевода целого из DEC в b делите на b и записывайте остатки в обратном порядке. 374/16 = 23 остаток 6, 23/16 = 1 остаток 7, 1/16 = 0 остаток 1; ответ 176₁₆.
Для перевода дроби из DEC в b умножайте её на b; целая часть произведения — очередная цифра. 0.125×16=2.0, значит 0.125₁₀ = 0.2₁₆. Поэтому 4.125₁₀ = 4.2₁₆ = 4.1₈ = 100.001₂.
Основание входных чисел и основание результата независимы. При Output base: 16 строка 9*6 = 36 означает 54₁₀ = 36₁₆, а не ошибку умножения. Префиксы слева относятся к входу, заголовок — к ответам справа.

## 14. Зачем нужен парсер
Парсер преобразует строку в структуру, показывающую порядок вычисления. Отправить всю строку вроде (0x10+010)*@10 обычному Калькулятору нельзя: смесь префиксов — формат нашей программы. Сначала необходимо распознать числа и операции.
Три уровня: atom — число, знак или скобки; term — * и /; expr — + и −. expr вызывает term, а term — atom; поэтому умножение обрабатывается до сложения. При открывающей скобке atom вызывает expr повторно до закрывающей.
Для 2+3*4 сначала создаётся узел умножения 3 и 4, затем узел сложения с 2. evaluate сначала получает ответы детей, затем выполняет родительскую операцию. Порядок запросов: 3*4 → 12, 2+12 → 14. Для (2+3)*4: 2+3 → 5, 5*4 → 20.
Унарный минус относится к одному операнду: -5. Бинарный минус — к двум: 8-5. Рекурсия — вызов функцией самой себя прямо или через другие функции; здесь она нужна для вложенных скобок и обхода дерева.
Проверки парсера: допустимость цифр для основания, наличие операнда, закрытие скобок, отсутствие лишних символов после выражения. «08» не должно частично приниматься за 0. «2(3)» не является поддерживаемым неявным умножением: нужно 2*3.

## 15. Как устроен PowerShell-мост
JScript создаёт запрос в UTF-16LE и запускает calculator.ps1. Мост читает параметры, находит процесс Калькулятора, активирует его окно, очищает состояние, вводит операнды и операцию. Затем получает ответ с дисплея через UI Automation либо из буфера обмена, записывает OK и число в ответный файл. JScript ждёт завершения, проверяет код и читает число.
UI Automation — интерфейс доступности и автоматизации Windows. Через AutomationElement можно найти элемент, через ValuePattern или TextPattern — получить значение/текст, если приложение поддерживает такой шаблон. AutomationId — имя элемента интерфейса; это не PID и не HWND. В разных версиях Калькулятора идентификаторы могут различаться, поэтому такой способ нельзя объявлять универсальным.
| Конструкция PowerShell | Что означает |
| param(...) | Объявление входных параметров скрипта. |
| $Request / $Response | Пути к запросу и ответу; знак $ обозначает переменную. |
| $ErrorActionPreference = 'Stop' | Перевод многих ошибок командлетов в прерывающие ошибки, обрабатываемые catch. |
| Add-Type -AssemblyName ... | Подключение сборки .NET для Forms/автоматизации. |
| New-Object -ComObject WScript.Shell | Создание того же COM-объекта оболочки из PowerShell. |
| Get-Process -Name ... | Поиск процессов по известным именам. Отсутствующее имя не доказывает отсутствие окна другой реализации. |
| Where-Object { ... } | Фильтрация найденных объектов. |
| Start-Process calc.exe | Запуск Калькулятора. |
| Start-Sleep -Milliseconds 500 | Задержка полсекунды. |
| [IO.File]::ReadAllLines(...) | Статический вызов .NET для чтения строк файла. |
| [Text.Encoding]::Unicode | UTF-16LE в используемом .NET API. |
| [double]::Parse(..., InvariantCulture) | Чтение десятичного числа в согласованном формате обмена. |
| try / catch / throw | Контроль ошибок и возврат ERROR вместо фиктивного результата. |
| exit 0 / exit 1 | Успех / ошибка процесса моста. |
Параметры запуска: -NoLogo убирает баннер, -NoProfile отключает пользовательские профили, -STA задаёт COM-apartment, -File выбирает сценарий, -Request/-Response — наши параметры. -ExecutionPolicy Bypass действует в дочернем процессе и не даёт прав администратора. Не следует ради лабораторной отключать защиту Windows или глобально менять политику.
Региональный формат: входные выражения используют точку; при наборе в Калькулятор десятичный разделитель приводится к текущей культуре Windows. Ответ возвращается в согласованном формате для Number(). Если язык приложения отличается от региональных настроек, чтение всё равно может требовать адаптации.

## 16. Ошибки: как искать причину по этапам
| Признак | Что проверить первым |
| «Файл не найден», строка открытия common.vbs | Совпадает ли комплект файлов с версией кода; нужен ли ему common.vbs. |
| Калькулятор открылся, но startup timed out | По каким именам процессов выполняется поиск; поддерживается ли классический calc/win32calc. Переустановка не следует автоматически. |
| На дисплее 54, а в Блокноте искажённый текст | SendKeys для кириллицы, раскладку и фокус; надёжнее Unicode-файл. |
| Calculator did not copy a result to the clipboard | Этап чтения результата, активное окно, реализацию копирования, текущую версию calculator.ps1. |
| Ошибка только у 08 | Недопустимая восьмеричная цифра 8. |
| Ошибка Missing closing parenthesis | Баланс круглых скобок во входной строке. |
| ERROR: Division by zero | Значение правого операнда деления, в том числе после вычисления скобок. |
| В HEX справа 36 вместо 54 | Это нормальный перевод 54₁₀ в 36₁₆. |
| При отмене виден старый text2.txt | Отмена не создаёт новый файл; смотрите дату и содержимое прошлого результата. |
| Выход содержит ERROR, но файл создан | Сам факт создания не доказывает успех; смотрите errors и код выхода. |
Порядок диагностики: воспроизведите на одном простом примере 9*6; посмотрите дисплей; проверьте чтение ответа; затем форматирование и запись. Не меняйте одновременно вход, версию сценария и настройки Windows — иначе невозможно понять причину изменения.

## 17. Точность, усечение и честная проверка
JScript Number — double: около 15–17 значащих десятичных цифр, безопасное целое не больше 2^53−1. Это не означает, что любая дробь с 15 цифрами представляется точно. Например, 0.1 не имеет конечной двоичной записи.
Ограничение 12 дробных цифр в format — отдельное ограничение вывода. Маркер [truncated] означает остаток после усечения. Точность Калькулятора может быть выше, но преобразование его ответа в Number снова ограничивает точность.
Проверка на известном эталоне отличается от подстановки эталона. Если сценарий получил 54 из Калькулятора и сравнил с 54 — это проверка. Если он при любой ошибке просто написал 54 — это не выполнение требования.
Тесты парсера с имитацией Калькулятора показывают, что правильно разобраны строки и вызваны операции. Они не проверяют горячие клавиши, буфер обмена и реальные окна Windows. Скриншот конечного файла показывает его содержимое, но не доказывает, что все невидимые ветви программы тестировались.

## 19. Ответы к упражнениям
1. calc.exe — команда, 1 — обычное активное окно, False — продолжить сценарий сразу. True может заставить ждать закрытия Калькулятора.
2. Например: cd /d "D:\Lab4", затем cscript.exe //nologo //E:JScript script3.js. /d меняет также активный диск.
3. F7 — две цифры HEX-числа; {F7} — функциональная клавиша; {+} — буквальный плюс; + — модификатор Shift.
4. 0x1A+2 = 28₁₀ = 1C₁₆. 010+@10 = 10₁₀ = A₁₆. 0xA.8+@1.1 = 12₁₀ = C₁₆. 010.4/2 = 4.25₁₀ = 4.4₁₆.
5. 2+3*4: корень +, справа узел *; запросы 3*4, затем 2+12. (2+3)*4: корень *, слева узел +; запросы 2+3, затем 5*4.
6. lineNumber соответствует физической строке входа и нужен в сообщении об ошибке. failures считает ошибочные выражения. Пустая строка не является выражением; при её пропуске нумерация строк всё равно продолжается.
7. В DEC: 54, 374, 10, 12, 14, 20, 4.25, 255. В HEX: 36, 176, A, C, E, 14, 4.4, FF. Заголовок вывода указывает основание ответов.
8. 1/0 — проверка деления в evaluate; 08 и @102 — проверка цифр в parse; (2+3 — проверка закрывающей скобки. Ошибки интерфейса Windows — другой класс, они не заменяют эти ожидаемые проверки.
9. Один выходной файл перезаписывается при каждом запуске, поэтому его копируют до следующего. Отмена может оставить старый результат.
10. WScript.ScriptFullName даёт путь; Popup 1+64 — ОК/Отмена и информационный значок. Возвращаемый код 1 — ОК, 2 — Отмена.

## 21. План ответа на защите
Начните с цели: «Я автоматизирую стандартные приложения Windows и обрабатываю файл выражений». Затем назовите хост WSH и два основных COM-объекта. Для первого задания расскажите цепочку запуск → активация → ввод → получение ответа → Блокнот. Для второго объясните HEX/DEC и F7 против {F7}. Для третьего — файл, диалог, парсер, дерево, мост, результат.
Покажите один простой пример вручную: 0xF7+0x7F = 374₁₀ = 176₁₆. После этого объясните, почему 2+3*4 и (2+3)*4 различаются. Завершите обработкой ошибок и границами проверки: какие результаты видны, какие ветви запускались, где встречались проблемы интерфейса.
Не говорите «всё работает», если в выходе есть ERROR или подпись искажена. Лучше точно указать: вычисление верно, но была ошибка передачи текста; исправление меняет механизм вывода, а не математический ответ.
